# Deploying Collabio on Render (PayPal hackathon build)

The Blueprint is `render.yaml` at the repo root. It creates three services in **Singapore**
(closest Render region to the Supabase project in `ap-south-1`), all on branch
`hackathon/paypal-money`:

| Service | Type | What it runs |
|---|---|---|
| `collabio-api` | Python web, Starter | FastAPI (`uvicorn app.main:create_app --factory`), health `/api/v1/health`, in-process workers (`WORKERS_ENABLED=1`) |
| `collabio-web` | Node web, Starter | Next.js (`npm ci && npm run build`, `npm run start`) |
| `collabio-nightly` | Cron, `0 3 * * *` UTC | `POST /api/v1/internal/nightly` with `X-Internal-Secret` (shared from the API via `fromService`) |

Supabase stays hosted: the same project the local `.env` files point at. Migrations and the
money seed are already applied there, so nothing runs against the database at deploy time.

## Environment

Values never live in git. `render.yaml` declares every key; secrets are `sync: false`.

## Steps

1. **Create the Blueprint.** Render dashboard → New → Blueprint → repo `Collabio`, branch
   `hackathon/paypal-money`. Secret prompts can be left empty if the form allows it (step 3 fills them).
2. **Render API key.** Account settings → API Keys → create one; put it in `backend/.env` as
   `RENDER_API_KEY=...` (git-ignored).
3. **Push the environment** (from `backend/`):
   ```bash
   uv run python -m scripts.render_env status
   uv run python -m scripts.render_env push --deploy
   ```
   It sets every key above from the local `.env` files, uses the services' real URLs, prints
   only key names, and redeploys the API and web services.
4. **PayPal webhook** (after the API is live):
   ```bash
   uv run python -m scripts.register_paypal_webhook https://<collabio-api URL>
   uv run python -m scripts.render_env set PAYPAL_WEBHOOK_ID=<printed id> --deploy
   ```
   Events: `PAYMENT.PAYOUTS-ITEM.*` and `PAYMENT.CAPTURE.REFUNDED` →
   `/api/v1/webhooks/paypal`. Until `PAYPAL_WEBHOOK_ID` is set, the webhook answers 202 and the
   payout worker still syncs statuses by polling.
5. **Stop the local backend's workers.** Local and hosted share one database; run the local
   API with `WORKERS_ENABLED=0` (or not at all) once Render is live.
6. **Reset the demo** so judges start clean: `uv run python -m scripts.seed_money`, then
   clear `public.usage_counters`.
7. **Verify in an incognito window** on the web URL: Brand persona → Deals → Lumen Pods
   launch → Fund with PayPal (sandbox buyer) → creator submits proof (sample screenshot) →
   Claude settles → payout → close deal → refund; then `/brand/money` and the agent.

## Render Workflows (settlement runs)

Workflows cannot be declared in a Blueprint yet, so the workflow service is created by hand:

1. Render dashboard → New → **Workflow** → repo `Collabio`, branch `hackathon/paypal-money`,
   name **`collabio-settlement`**, region Singapore.
   - Root directory: `backend`
   - Build command: `pip install uv && uv sync --frozen --no-dev`
   - Start command: `uv run --no-sync python -m workflows.settlement`
   - Environment: the same database, PayPal, Anthropic and Supabase keys as `collabio-api`
     (`SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `SUPABASE_DB_URL`, `PAYPAL_CLIENT_ID`,
     `PAYPAL_CLIENT_SECRET`, `PAYPAL_RECEIVER_EMAIL`, `ANTHROPIC_API_KEY`, `HACKATHON_MODE=1`,
     `PYTHON_VERSION=3.12.8`). An environment group shared with `collabio-api` is easiest.
2. After it deploys, its **Tasks** page lists `settle_submission` and `nightly_settlement`;
   the slugs are `collabio-settlement/settle_submission` and `collabio-settlement/nightly_settlement`.
3. On `collabio-api` set `RENDER_API_KEY` and `RENDER_WORKFLOWS_ENABLED=1`:
   ```bash
   uv run python -m scripts.render_env set RENDER_WORKFLOWS_ENABLED=1 --deploy
   ```
4. Submit a proof on the hosted app; a `settle_submission` run appears on the workflow's Tasks
   page. If triggering ever fails, the API logs a warning and settles in-process instead, and a
   run is idempotent per submission, so it can never pay twice.

## Cost

Two Starter web services (about $7/month each) and a cron job, paid from the $50 Render
hackathon credits. Free instances are avoided because they spin down.
